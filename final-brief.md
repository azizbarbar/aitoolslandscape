## The map stays fixed

- Origin at the center. Both axes have equal scale and run from −1 to +1.
- Horizontal: **GENERATIVE** at −1, left; **GROUNDED** at +1, right.
- Grounded means working from supplied material: evidence-bound, input-preserving. Generative means producing new possibilities.
- Vertical: **PROPOSES DIRECTIONS** at −1, bottom; **EXECUTES MY DECISIONS** at +1, top.
- The vertical axis describes the design agency delegated by the human, not the number of automated steps.

The two soft horizontal bands span both columns:

- Upper: **CONTROLLED COLLABORATOR** — “I establish the design direction and delegate bounded production work.”
- Lower: **CURATOR / DIRECTOR** — “I invite AI to propose directions, then select, critique and develop them.”

These describe ways of working, not types of AI.

Quadrant names remain:

| | Generative | Grounded |
|---|---|---|
| Executes my decisions | DIRECTED EXPERIMENTATION | GROUNDED PRODUCTION |
| Proposes directions | OPEN EXPLORATION | CONSTRAINED PROPOSALS |

## Scoring: evidence first, editorial calibration second

Keep two separate records internally: the evidence-based profile and the final visual profile. The page presents the visual profile. This separation supports deliberate visual editing without rewriting what a source actually says.

### Evidence-based profile

Use eight directional scores: N, NE, E, SE, S, SW, W, NW, plus an illustrative default position. Retain the 0–4 anchors in `method.md`, with the following refinements:

- Allow quarter-point increments when documented differences justify a position between integer anchors. Explain the relevant capability and limitation; decimals are editorial resolution, not measurement precision.
- Use the same anchors across all categories. A tool does not acquire a different meaning for “grounded” merely because its neighbors are different.
- Score the actual scoped product and workflow, not the union of every model, connector, or promotional claim associated with its brand.
- Distinguish default behavior from what a tool can reach with deliberate use.
- Do not treat citations as exact preservation, autonomous step count as decision precision, or paraphrasing as broad invention.
- Diagonals describe capabilities used together. Separate features do not automatically establish a strong combined workflow.
- Every evidence score needs a claim, official source URL, confidence, and an explicit indication where the placement is inferred.

The four cardinal directions establish the broad capability limits. Diagonals and the default position supply much of the character: where the cloud leans, where it narrows, and which combinations it does not comfortably support.

### Editorial calibration within a completed category

Review every category only after its initial profiles are complete. Compare the tools together and identify their most useful documented distinctions for the workshop.

- First refine the profiles using real differences in conditioning, preservation, novelty, local control, proposal behavior, and combined workflows.
- Then accentuate subtle distinctions if needed: a more pronounced lobe, a tighter indentation, a narrower span, or a slight shift in the cloud's center.
- Prefer directional and asymmetric changes over uniformly enlarging or shrinking a cloud.
- Allow an editorial score adjustment of up to ±0.5 on the 0–4 scale and a center shift of up to ±0.10 on either map axis. These are maximum allowances, not targets or automatic offsets.
- Do not push a profile beyond a documented hard capability limit, turn an unsupported operation into a supported one, or conceal a discontinued status.
- Do not invent a contrast solely because two genuinely similar tools share a profile. Their motion and text can still make their different workflows clear.
- Keep all tools within the fixed −1 to +1 map. Do not rescale the axes separately for each category.

Record the initial profile, adjusted profile, reason for each change, and reviewer decision in `calibration-log.md`. These records belong in the project, not in a persistent on-screen explanation. The optional score readout shows the final editorial values that actually generate the displayed geometry.

### Geometry and motion

Use a deterministic geometry function: the same final profile must always produce the same shape. Retain the cardinal-bound and diagonal-point construction in `method.md`, applying it to the final visual scores and center. Clamp the shifted center to its final bounds. Preserve diagonal compatibility constraints and record derived vertices in the data.

Fit a smooth closed contour with controlled local rounding. Preserve meaningful indentations and avoid spline overshoot beyond supported limits. Do not add arbitrary random wiggles to make clouds look different. A narrow or asymmetric operating profile should remain narrow or asymmetric.

Selecting the first tool traces its cloud onto the map. Replacing a tool morphs between the ordered directional shapes. Adding a comparison draws a second distinct contour. During a morph, the moving contour is a visual transition, not an additional scored state. Respect reduced-motion preferences with an immediate or short-fade alternative.

## The page

One view, dominated by the map. A compact category selector and a list of tool names with monochrome logos provide the primary controls. Avoid a dashboard, landing-page hero, card grid, or multi-page structure.

- Select one tool to show its cloud and name.
- Select a second tool to overlay it for comparison; two active tools maximum.
- Make removal and replacement obvious, without accumulating more than two clouds.
- Provide a quiet option to show every tool in the category as faint outlines.
- Keep a short interpretation beside the map. Put the eight scores and evidence links in a compact expandable detail area so they do not dominate the initial composition.
- Use a small “How this map is scored” panel. Describe the map briefly as an interpretive teaching map, not an accuracy benchmark. Do not add an exaggeration label or calibration controls.
- Number keys 1–4 select categories. Arrow keys operate the focused category or tool list. Tab moves between controls. Enter/Space select. Esc clears selected clouds. Avoid shortcuts interfering with expanded controls or text selection.

Use progressive disclosure for detail, not tiny text. Essential map labels and selected-tool names must remain legible when projected.

## Visual direction

Swiss and editorial typography meeting a restrained terminal/dot-matrix language. High design culture, deliberate spacing, and a confident composition. Slightly ASCII; never retro-gimmicky.

- White background; ink `#111111`; secondary gray `#6B6B6B`; hairlines `#D9D9D9`.
- Controlled Collaborator band: flat lavender wash `#DCD3E8` (text `#58467E`). Updated 15 Oct 2026 to match How Machines Think draft 2.
- Curator / Director band: flat blue wash `#E0E9F2` (text `#3E5C80`). No gradient between the bands.
- Sage `#3B6447` (wash `#DAE6D3`) for the human check and blush `#9A3443` (wash `#F4D9DB`) for failures, only where needed.
- VT323 for titles and large labels. IBM Plex Mono for all other text. Copy and load the supplied fonts locally from `../../How Machines Think Presentation/fonts/`.
- Fine axes, precise ticks, and ample whitespace. Structural rules should organize the map rather than decorate it.
- Cloud interiors use restrained dithered character fields, such as `· : + ✳`, enclosed by a clean smooth contour. Treat glyph density as graphic texture, not a confidence score.
- The comparison cloud uses a distinctly different outline and fill treatment that remains recognizable in monochrome.
- Use supplied black logo PNGs from `../../How Machines Think Presentation/_source/assets/logo/`. Obtain missing real logos from `@lobehub/icons-static-svg` or `simple-icons` during preparation and save them locally. If unavailable, use a clean text label; never invent a logo.

Desktop only, as requested in the final implementation steering. Aim for a composition that works at 1920×1080 from the back of a lab and remains comfortable at 1366×768 on a laptop. Mobile is outside the delivery and acceptance scope; an existing narrow-screen fallback may remain.

## Technical delivery

Everything lives in `The Tools Landscape/delegation-map/`.

- Plain HTML, CSS, and JavaScript, with SVG or canvas for the map.
- No build step, CDN assets, or network requests at runtime.
- Browser data in `data.js` so double-clicking `index.html` works through `file://`.
- Editable research and geometry data in `scores.json`.
- Include `method.md`, `calibration-log.md`, local fonts and logos, a validation script, and a five-line `README.md`.
- Keep this consolidated brief as `final-brief.md`.
- American English throughout.

Windows convenience scripts:

- `start-server.bat`: check/install Node.js if missing, launch the local server, wait for readiness, and open the default browser. No npm dependencies are needed for the current static server. Installation may require an internet connection on first use; the finished page itself works offline.
- `stop-server.bat`: stop only the preview server belonging to this project.
- Repeated launches reuse the running server. Starting from a folder path containing spaces must work. Keep background server windows hidden.

The existing server helpers have passed launch, repeated launch, serving, protected-state, shutdown, and repeated-shutdown checks. The Node.js installation path was not exercised because Node.js was already installed.
